# moddotplot-rs

> **Authorship note:** This document was generated by ChatGPT 5.6 Sol. The software
> was written by ChatGPT 5.6 Sol under the guidance of Adam Phillippy.

moddotplot-rs is an install-free, browser-native interactive dotplot for genomic
sequences. Rust and WebAssembly perform the scientific calculation in a dedicated
worker, while a small TypeScript/WebGL2 application provides progressive rendering,
pan and zoom, orientation coloring, and genome feature tracks.

Sequence and annotation data remain inside the browser. The production application
has no runtime server API, CDN dependency, analytics, or telemetry.

> **v0.1 status:** functional preview, not yet a research-validated release. The user
> interface and core calculation are working and tested. Robust 1 Gb operation,
> current CHM13 performance measurements, cross-browser visual testing, and broader
> validation of the probabilistic sparse policy remain release gates. See
> [Implementation status](docs/STATUS.md).

## Features

* Load multi-file, multi-record FASTA or gzip FASTA without uploading data
* Select any loaded sequence independently for the X and Y axes
* Render a genuine 500, 1,000, 2,000, or 4,000-cell overview matrix
* Show a fast configurable quick estimate, then refine it asynchronously
* Pan and zoom through cached 256 by 256 tiles with coarse-level visual fallback
* Switch between containment-derived ANI and forward/reverse orientation coloring
* Reach an exact canonical k-mer dotplot at terminal zoom
* Recolor cached results with an interactive 80% to 100% identity transfer function
* Add validated BED3-12, GFF3, or GTF feature tracks to either axis
* Monitor foreground progress and estimated application memory

The production backend uses rolling ntHash2, one-permutation b-bit signatures, HLL
cardinality, and bounded exact correction for statistically sparse detailed windows.
The displayed estimate is `ANI = containment^(1/k)`. Minmer and MashMap-compatible
implementations remain in the repository as tested scientific references; minmers are
not the current browser sketch.

## Use the application

End users do not install Rust, Node.js, or any package. Open a deployed HTTPS build in
a current desktop Chrome, Edge, Firefox, or Safari, then drop in FASTA files. See the
[user guide](docs/USER_GUIDE.md) for controls, annotations, interpretation, privacy,
and troubleshooting.

A production build must be served over HTTP or HTTPS. Browser security restrictions
mean that double-clicking `index.html` through a `file://` URL is not supported.

## Developer setup

### Prerequisites

* A current stable Rust toolchain supporting edition 2024
* The Rust `wasm32-unknown-unknown` target
* [`wasm-pack`](https://rustwasm.github.io/wasm-pack/)
* Node.js 22 or newer and npm
* A desktop browser with WebAssembly, Web Workers, and WebGL2

Install the Rust target and `wasm-pack` if they are not already available:

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-pack
```

Install the locked browser development dependencies:

```sh
npm --prefix web ci
```

### Run locally

Build the Wasm package, then start the development server:

```sh
npm --prefix web run build:wasm
npm --prefix web run dev
```

Open the local URL printed by Vite. Source edits are reflected by the development
server; rebuild Wasm after changing Rust code exposed to the browser.

### Build static assets

```sh
npm --prefix web run build:wasm
npm --prefix web run build
```

The deployable site is written to `web/dist/`. It can be placed on any static HTTPS
host. No application backend is required.

## Dependencies

The dependency surface is intentionally small:

| Component | Runtime dependencies |
| --- | --- |
| `moddotplot-core` | None |
| `moddotplot-phase0` | `moddotplot-core` only |
| `moddotplot-wasm` | `wasm-bindgen`, `serde`, `serde-wasm-bindgen`, and panic-hook support |
| Browser application | Generated Wasm and browser platform APIs; no runtime JavaScript library |

TypeScript, Vite, and Vitest are development dependencies pinned by
`web/package-lock.json`. Exact Rust dependency versions are pinned by `Cargo.lock`.
See [third-party notices](THIRD_PARTY_NOTICES.md).

## Test and validate

Run the complete local validation sequence:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo check -p moddotplot-wasm --target wasm32-unknown-unknown
npm --prefix web test
npm --prefix web run build:wasm
npm --prefix web run build
```

Reproduce the frozen Phase 0 synthetic benchmark with:

```sh
cargo run --release -p moddotplot-phase0 -- \
  --output docs/benchmarks/phase0-synthetic.tsv
```

Scientific changes must retain differential tests against the exact or scalar
reference path and update the relevant benchmark evidence. Performance changes may not
relax correctness gates.

## Engineering principles

* Public scientific APIs define coordinate and ambiguity semantics.
* Fixed integer hashing and seeds make sketches reproducible across browsers.
* Optimized kernels are differentially tested against simple reference code.
* Numeric tile generation is independent of WebGL and reserved for future export.
* Active tile keys are immutable across scientific parameters and quality tiers.
* Correctness and reproducibility take priority over throughput.
