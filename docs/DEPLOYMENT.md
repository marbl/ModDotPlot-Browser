# Local installation and HPC deployment

> **Note:** This project was generated by ChatGPT 5.6 Sol under the direction of Adam Phillippy and Alex Sweeten. For analyses intended for publication, please use the official [ModDotPlot CLI](https://github.com/marbl/ModDotPlot) and cite the [ModDotPlot paper](https://doi.org/10.1093/bioinformatics/btae493).

`ModDotPlot Browser` is a static Rust/WebAssembly web application. After it has been
built, it does not require an application server or database. A web server only
delivers the static files; FASTA parsing, dotplot computation, and rendering happen
inside the user's browser.

## Requirements

The current build uses:

- Git
- Node.js 25.9.0
- npm
- Rust 1.98.0
- The Rust `wasm32-unknown-unknown` target
- `wasm-pack` 0.15.0
- A modern browser supporting WebAssembly, Web Workers, WebGL2, and
  `DecompressionStream`

The required Node.js and Rust versions are also recorded in `.node-version` and
`rust-toolchain.toml`.

## Local installation

### 1. Download the source code

The recommended method is to clone the `main` branch:

```bash
git clone https://github.com/marbl/ModDotPlot-Browser.git
cd ModDotPlot-Browser
```

Alternatively, download the source without Git:

```bash
curl -L \
  https://github.com/marbl/ModDotPlot-Browser/archive/refs/heads/main.zip \
  -o ModDotPlot-Browser-main.zip

unzip ModDotPlot-Browser-main.zip
cd ModDotPlot-Browser-main
```

If you intend to customize the application, fork the repository and clone your fork
instead.

### 2. Install Node.js

If `nvm` is already installed, use the version recorded by the repository:

```bash
source "${NVM_DIR:-$HOME/.nvm}/nvm.sh"
nvm install "$(cat .node-version)"
nvm use "$(cat .node-version)"
```

Confirm the versions:

```bash
node --version
npm --version
```

Node.js should report version `25.9.0`.

### 3. Install Rust

If Rust is not already installed:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs \
  | sh -s -- -y --profile minimal

source "$HOME/.cargo/env"
```

Install the pinned Rust toolchain and WebAssembly target:

```bash
rustup toolchain install 1.98.0 \
  --profile minimal \
  --component rustfmt \
  --component clippy \
  --target wasm32-unknown-unknown
```

Install the pinned version of `wasm-pack`:

```bash
cargo install wasm-pack --version 0.15.0 --locked
```

Verify the installation:

```bash
rustc --version
cargo --version
wasm-pack --version
```

### 4. Install dependencies and build

Install the exact JavaScript dependencies recorded in `package-lock.json`:

```bash
npm --prefix web ci
```

Build the Rust/WebAssembly code and static website:

```bash
npm --prefix web run build
```

The deployable website is written to:

```text
web/dist/
```

The build also runs the TypeScript tests, prepares the bundled *Arabidopsis thaliana*
example, generates the WebAssembly bindings, checks the documentation contracts, and
updates the software dependency inventory.

### 5. Launch locally

Start the included preview server:

```bash
npm --prefix web run preview -- \
  --host 127.0.0.1 \
  --port 4178 \
  --strictPort
```

Open the following address in a browser:

```text
http://127.0.0.1:4178
```

Keep the terminal running while using the application. Stop the server with
`Control-C`.

If port `4178` is already in use, choose another port:

```bash
npm --prefix web run preview -- \
  --host 127.0.0.1 \
  --port 4180 \
  --strictPort
```

Then open:

```text
http://127.0.0.1:4180
```

## HPC deployment

There are two common ways to use `ModDotPlot Browser` on an HPC system:

1. Build and run the static server on the HPC system, then reach it through an SSH
   tunnel.
2. Install `web/dist/` on an institutional Apache, Nginx, or Open OnDemand web server.

Please note that each HPC environment has its own policies regarding software installation, network access, and resource usage. Before installing or running `ModDotPlot Browser`, consult your cluster’s documentation and follow local guidelines for job submission and the use of login and compute nodes. Contact your HPC administrators if you are unsure what is permitted or need help setting up the software.

### Important data-location behavior

The application runs wherever the browser runs.

If `ModDotPlot Browser` is served by an HPC system but opened in a browser on a laptop:

- Computation occurs on the laptop.
- Browser memory on the laptop determines the practical dataset limit.
- The file picker sees files on the laptop, not arbitrary paths on the HPC filesystem.
- Allocating more HPC CPUs or GPUs does not accelerate the browser on the laptop.
- FASTA and annotation files selected through the browser are not uploaded to the web
  server.

To open files stored on an HPC filesystem, use one of the following approaches:

- Copy the files to the local workstation with `scp`, SFTP, or Globus.
- Mount the HPC filesystem locally with SSHFS.
- Run the browser inside an Open OnDemand or VNC remote desktop.
- Ask an HPC administrator to provide an authenticated data-serving integration.

**Do not place private genomic data in a publicly accessible web directory!**

### Option 1: Build directly on the HPC system

Clone the repository:

```bash
git clone --branch main https://github.com/marbl/ModDotPlot-Browser.git
cd ModDotPlot-Browser
```

Many HPC systems provide Node.js and Rust through environment modules. Available module
names vary by cluster:

```bash
module spider node
module spider rust
```

Load suitable versions if available:

```bash
module load nodejs/25.9.0
module load rust/1.98.0
```

If the cluster does not provide these modules, install Node.js and Rust in the user
account using the local installation instructions above.

Ensure that the WebAssembly target and `wasm-pack` are available:

```bash
rustup target add wasm32-unknown-unknown \
  --toolchain 1.98.0

cargo install wasm-pack --version 0.15.0 --locked
```

Build the application:

```bash
npm --prefix web ci
npm --prefix web run build
```

If compute nodes do not have outbound internet access, perform dependency installation
on a login or designated build node. Follow the local HPC policy regarding compilation
on login nodes.

### Option 2: Build locally and copy the static site to the HPC system

This option avoids installing Rust on the HPC system.

Build the application on a local computer:

```bash
cd ModDotPlot-Browser

npm --prefix web ci
npm --prefix web run build
```

Package the generated static site:

```bash
tar -C web/dist \
  -czf moddotplot-browser-v1.0.0-dist.tar.gz \
  .
```

Copy it to the HPC system:

```bash
scp moddotplot-browser-v1.0.0-dist.tar.gz \
  USER@login.cluster.example.edu:/path/to/destination/
```

On the HPC system:

```bash
mkdir -p /path/to/moddotplot-browser-v1.0.0

tar -xzf /path/to/destination/moddotplot-browser-v1.0.0-dist.tar.gz \
  -C /path/to/moddotplot-browser-v1.0.0
```

The extracted directory is the complete static website. It can be published through
Apache, Nginx, Open OnDemand, or another static server.

### Temporary personal HPC session

For a temporary personal session, use the repository's preview server. This method
requires Node.js and the installed `web/node_modules` dependencies on the HPC system.

From the repository checkout:

```bash
npm --prefix web ci
```

If `web/dist/` has not already been built:

```bash
npm --prefix web run build
```

Start the server:

```bash
npm --prefix web run preview -- \
  --host 127.0.0.1 \
  --port 4178 \
  --strictPort
```

Leave this process running.

#### Server running on the login node

On the local workstation, open a second terminal and create an SSH tunnel:

```bash
ssh -N \
  -L 4178:127.0.0.1:4178 \
  USER@login.cluster.example.edu
```

Open:

```text
http://127.0.0.1:4178
```

Do not run a long-lived server on a login node unless cluster policy permits it.

#### Server running on a Slurm compute node

Request an interactive allocation:

```bash
srun \
  --pty \
  --time=04:00:00 \
  --cpus-per-task=1 \
  --mem=2G \
  bash
```

On the allocated node, record its hostname:

```bash
hostname -f
```

Start `ModDotPlot Browser` from the repository checkout:

```bash
cd /path/to/ModDotPlot-Browser

npm --prefix web run preview -- \
  --host 127.0.0.1 \
  --port 4178 \
  --strictPort
```

On the local workstation, tunnel through the login node to the allocated compute node:

```bash
ssh -N \
  -J USER@login.cluster.example.edu \
  -L 4178:127.0.0.1:4178 \
  USER@COMPUTE_NODE
```

Replace:

- `USER` with the HPC username.
- `login.cluster.example.edu` with the login host.
- `COMPUTE_NODE` with the hostname returned by `hostname -f`.

Open:

```text
http://127.0.0.1:4178
```

Some clusters do not permit direct SSH connections to compute nodes. In that case, use
the cluster's documented multi-hop tunneling procedure or Open OnDemand.

### Persistent shared HPC deployment

For a shared deployment, publish `web/dist/` through an institutional static web server.

For example:

```bash
mkdir -p /path/to/web/root/moddotplot
cp -a web/dist/. /path/to/web/root/moddotplot/
```

If the application is served from the root of a domain:

```text
https://moddotplot.example.edu/
```

the default build is sufficient.

If it is served below a URL prefix:

```text
https://tools.example.edu/moddotplot/
```

rebuild with the prefix, including the leading and trailing slashes:

```bash
MODDOTPLOT_BASE_PATH=/moddotplot/ \
  npm --prefix web run build
```

Then deploy the new contents of `web/dist/`.

The static server should:

- Serve `.wasm` files using the MIME type `application/wasm`.
- Support HTTP byte-range requests.
- Preserve `Range`, `Content-Range`, and `Content-Length` headers.
- Serve bundled `.gz` files as binary files without automatically adding a
  `Content-Encoding` header.
- Permit JavaScript module workers.
- Use HTTPS for a remotely shared deployment.

Byte-range support is important for indexed access to the bundled example FASTA.

### Open OnDemand

Open OnDemand is often the easiest way to use files directly from an HPC filesystem.

Two possible configurations are:

1. Publish `web/dist/` as a static institutional application. In this arrangement, the
   browser still runs on the user's workstation and cannot directly select arbitrary
   HPC paths.
2. Launch an Open OnDemand interactive desktop and open `ModDotPlot Browser` inside the
   remote desktop's browser. The browser file picker can then access files visible on
   the HPC filesystem.

The second configuration is recommended when large FASTA files should remain on the
HPC system.

## Customizing a deployment

Edit source files rather than editing `web/dist/`, because every build replaces
`web/dist/`.

Common customization locations include:

```text
web/index.html                       Landing-page content
web/src/styles.css                   Application styling
web/src/                             TypeScript application code
web/public/moddotplot-browser.gif    Animated landing logo
web/public/browser_1.png             Social-link preview
web/public/                          Other static files
web/package.json                     Application version
```

After making changes:

```bash
npm --prefix web run build
```

Restart the preview server or copy the updated `web/dist/` directory to the persistent
web-server location.

## Updating an installation

For an unmodified checkout:

```bash
cd ModDotPlot-Browser
git switch main
git pull --ff-only

npm --prefix web ci
npm --prefix web run build
```

Restart the preview server or redeploy `web/dist/`.

Custom installations should be maintained in a separate Git branch or fork. Merge
updates from the upstream `main` branch rather than overwriting local changes.
