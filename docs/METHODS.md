# Methods

> **Note:** This project was generated by ChatGPT 5.6 Sol under the direction of Adam Phillippy and Alex Sweeten. For analyses intended for publication, please use the official [ModDotPlot CLI](https://github.com/marbl/ModDotPlot) and cite the [ModDotPlot paper](https://doi.org/10.1093/bioinformatics/btae493).

## How the algorithm works

ModDotPlot Browser preserves the central idea introduced in the original
[ModDotPlot publication](https://doi.org/10.1093/bioinformatics/btae493): construct an
alignment-free dot plot by comparing sketches of canonical *k*-mers in genomic intervals.
However, the browser uses a new sketching and rendering implementation designed for
bounded memory, progressive computation, WebAssembly, and interactive zooming.

The browser is therefore not a line-for-line port of the published Python ModDotPlot
algorithm. It retains the containment-based scoring model and window-expansion strategy,
but replaces hierarchical modimizers with one-permutation hashing and cardinality
estimation.

*For this reason, we recommend using `ModDotPlot Browser` only for exploratory analysis.*

### 1. One-permutation sketches

The published ModDotPlot algorithm uses hierarchical modimizers. ModDotPlot Browser
instead summarizes each interval with an undensified one-permutation hash sketch,
abbreviated **OPH**.

For a sketch containing `m` registers:

1. The upper hash bits assign each canonical *k*-mer to one register.
2. The smallest complete hash assigned to a register becomes that register's winner.
3. Empty registers remain empty; they are not filled or densified.
4. A 32-bit winner fingerprint is retained for scientific comparison.
5. Orientation bits record whether the winning canonical *k*-mer was observed on the
   forward strand, reverse strand, or both.

The default sketch sizes are:

```text
Preview:   256 registers
Detailed: 1,024 registers
```

The 256-register sketch is intended to paint a fast provisional overview. Selected
tiles are subsequently recomputed with 1,024 registers when the preview has weak
support or lies close to a display threshold.

### 2. Estimating Jaccard similarity

For two interval sketches, let:

```text
U = registers occupied in at least one sketch
M = occupied registers whose verified 32-bit winners match
```

The estimated Jaccard similarity is:

```text
J_hat = M / U
```

This is the matched-bin OPH estimator. A smaller 14-bit comparison is used as an
execution prefilter, but a scientific match is accepted only after the 32-bit winner
fingerprints agree.

### 3. Estimating set cardinalities and containment

Each interval also maintains a HyperLogLog cardinality estimate using precision 10.
This estimates the number of distinct canonical *k*-mers in each interval.

Given estimated Jaccard similarity `J` and estimated cardinalities `|A|` and `|B|`, the
intersection is estimated as:

```text
I_hat = J × (|A| + |B|) / (1 + J)
```

Directed containment is then:

```text
C_hat(A in B) = clamp(I_hat / |A|, 0, 1)
```

Containment is directional: a short repeat may be almost completely contained in a
larger interval even when the larger interval is not contained in the shorter one.

### 4. Computing the displayed score

For core intervals `X` and `Y`, and expanded intervals `X+` and `Y+`, the browser
computes containment in both directions:

```text
C_x = containment(X, Y+)
C_y = containment(Y, X+)
C   = max(C_x, C_y)
```

The displayed score is:

```text
ANI_c = C^(1/k)
```

The maximum directed containment is used so self-comparison matrices remain symmetric
and so a strong match can be detected when either core interval is contained within the
expanded interval on the opposite axis.

The value is stored as:

```text
round(ANI_c × 10,000)
```

A stored value of `10,000` represents 100%, while `65,535` is reserved for missing data.

### 5. Orientation and direction coloring

When matching canonical sketch winners have the same unambiguous source orientation,
they contribute a forward vote. Opposite source orientations contribute a reverse
vote.

Direction is summarized as:

```text
direction = (forward - reverse) / (forward + reverse)
```

Positive values indicate forward-oriented similarity and negative values indicate
reverse-complement similarity. Palindromic or otherwise ambiguous observations do not
force either direction.

Direction coloring changes the presentation of a tile but does not change its
containment or `ANI_c` score.

### 6. Progressive computation

The browser does not precompute every zoom level before displaying a plot.

Instead:

1. A 256-register overview is computed and painted incrementally.
2. Completed blocks can appear before the complete axes have finished preparing.
3. Tiles with weak evidence or values near display thresholds are selected for
   1,024-register refinement.
4. Detailed tiles replace compatible preview tiles as they become available.
5. Panning or zooming cancels obsolete work.
6. Previously computed tiles are retained in a bounded browser cache.
7. Zoomed regions are recomputed on demand at the required genomic scale.

This produces a responsive first view without requiring all possible zoom matrices to
be held in memory.

### 7. Exact terminal zoom

When the displayed interval reaches one matrix position per base, the approximate
sketch estimator is no longer used. The browser switches to exact canonical *k*-mer
comparison.

At this resolution:

- Equal valid canonical *k*-mers match exactly.
- Unequal valid *k*-mers are mismatches.
- *K*-mers overlapping ambiguous bases are missing.
- A match is drawn across its complete k-base footprint.
- Forward matches produce forward diagonals.
- Reverse-complement matches produce reverse diagonals.
- Reverse-complement-palindromic *k*-mers have neutral direction evidence.

The default exact view colors matches by the corresponding base from the X sequence.
An identity-colored exact view is also available. Changing exact-view colors does not
change the underlying exact match matrix.

## How this differs from the published ModDotPlot algorithm

The browser retains the published method's high-level containment model but changes its
sketch representation, execution strategy, and interactive rendering architecture.

| Component | Published ModDotPlot | ModDotPlot Browser |
| --- | --- | --- |
| Primary implementation | Python with Plotly, Dash, Flask, NumPy, and Plotnine | Rust compiled to WebAssembly with TypeScript and WebGL2 |
| Execution location | Python process on a workstation, server, or HPC node | Locally inside the user's browser |
| *K*-mer hash | MurmurHash3 | Rolling canonical ntHash2 |
| Sketch type | Hierarchical modulo sketches called modimizers | Undensified one-permutation hashing |
| Sketch size | Approximately 1,000 modimizers per window | 256 preview or 1,024 detailed OPH registers |
| Repetitive-window correction | Adaptively reduces modimizer sparsity when too few modimizers are selected | Not used in the production browser |
| Set comparison | Direct intersection of selected modimizer sets | Verified OPH winner matches divided by union-occupied registers |
| Cardinality handling | Modimizer-set sizes and a fractional-minhash containment correction | HyperLogLog precision 10 plus OPH-estimated Jaccard |
| Window-offset correction | Expands the target window by half a window on each side | Preserved using reusable half-window summaries |
| Interactive hierarchy | Precomputes full matrices for multiple hierarchical modimizer levels | Computes an overview, selectively refines uncertain tiles, and builds zoom tiles on demand |
| Zoom storage | Multiple complete similarity matrices | Bounded prepared-axis and tile caches |
| Terminal zoom | Limited by the minimum precomputed window size | Switches to exact canonical *k*-mer comparison at one base per cell |
| Orientation display | Primarily identity heatmaps | Identity or support-aware forward/reverse orientation coloring |
| Multiple sequences | Self and pairwise matrices generated by the CLI | Self, pairwise, and interactive grids of up to six sequences |
| Annotations | Not part of the core paper algorithm | Local BED, GFF3, GTF, GC%, and CpG tracks |
| Output | Static plots, interactive Dash plots, and compressed matrix data | Interactive WebGL plots, images, BEDPE, and an official-CLI configuration package |

### Why the sketch method changed

Hierarchical modimizers are effective in the command-line implementation because they
form nested sketches that can be reused across precomputed zoom levels. In a browser,
however, retaining complete modimizer sets and several full matrices can require
substantial memory for chromosome- or genome-scale input.

The browser's OPH representation provides a fixed-size summary for each interval.
HyperLogLog supplies a compact estimate of the corresponding distinct *k*-mer
cardinality. Together, these allow containment to be estimated without retaining the
complete *k*-mer set or a full hierarchy of precomputed matrices.

The browser also separates fast first paint from detailed computation. A small sketch
can paint an overview quickly, while more expensive sketches are reserved for cells
where additional evidence is likely to affect the display.
