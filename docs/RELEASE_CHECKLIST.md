## Automated validation

Run from the repository root and record the commit and tool versions in the release
notes:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo check -p moddotplot-wasm --target wasm32-unknown-unknown
npm --prefix web ci
npm --prefix web test
npm --prefix web run build:wasm
npm --prefix web run build
```

- [x] All commands pass in the prepared working tree; rerun after creating the proposed
      release commit.
- [x] The generated `web/dist/` contains no source maps, analytics, CDN references, or
      unplanned runtime network dependencies.
- [ ] A clean checkout reproduces the production bundle.

## Browser acceptance

Manually test the production build in current desktop Chrome, Edge, Firefox, and
Safari with a self-comparison and a two-record comparison.

- [ ] FASTA and gzip FASTA loading, progress, and errors
- [ ] X/Y selection, similarity/orientation switch, and recoloring
- [ ] Wheel zoom, pan, rapid cancellation, reset, resize, and cache eviction
- [ ] Quick viewport paints before detailed construction begins
- [ ] Exact k-mer terminal mode and base palette
- [ ] BED, BED12, GFF3, and GTF record validation and box-and-stick rendering
- [ ] Clear and reload behavior, including memory reporting
- [ ] Worker failure and WebGL context loss/recovery
- [ ] No application network requests containing input data

## Large-input gate

- [ ] Implement sharded packed sequences and sketches.
- [ ] Implement bounded transient OPFS spill or revise the supported input limit.
- [ ] Validate controlled behavior under allocation pressure.
- [ ] Measure and document practical limits on each supported browser.

The parser's 1 Gb hard limit alone is not sufficient to claim that 1 Gb records are
operationally supported.
