# moddotplot-rs user guide

> **Authorship note:** This document was generated by ChatGPT 5.6 Sol. The software
> was written by ChatGPT 5.6 Sol under the guidance of Adam Phillippy.

moddotplot-rs creates interactive comparative genomic dotplots entirely in a desktop
browser. Your sequence and annotation files are processed locally and are not uploaded
by the application.

## Supported browsers

Use a current desktop version of Chrome, Edge, Firefox, or Safari with WebAssembly,
Web Workers, and WebGL2 enabled. Mobile browsers are not supported in v0.1.

The application must be opened from an HTTP or HTTPS address. A downloaded build will
not work reliably by double-clicking `index.html`, because browsers restrict module
workers and WebAssembly on `file://` pages.

## Create a plot

1. Drop one or more FASTA or gzip-compressed FASTA files on the input area, or use the
   file chooser.
2. Wait for the sequence records to appear. The status line reports loading,
   signature construction, tile drawing, and refinement progress.
3. Choose a sequence for the X axis and one for the Y axis. Selecting the same record
   on both axes creates a self-dotplot.
4. Explore immediately when the quick view appears. A higher-accuracy view replaces
   its tiles after the quick viewport has been painted.

Multiple records and files may be loaded together. Each FASTA record is an independent
axis choice. A single record may contain up to 1,000,000,000 bases, although practical
very-large-record support remains limited by browser memory in v0.1.

## Read the plot

In **Similarity** mode, each pixel summarizes one interval on the X axis against one
interval on the Y axis. Color represents a containment-derived identity estimate:

```text
ANI = containment^(1/k)
```

Containment is evaluated in both core-versus-expanded directions and the larger value
is displayed. The expansion makes the plot less sensitive to two homologous intervals
falling slightly out of register with the matrix grid.

The default heatmap is white below 80% identity and follows the yellow-red-dark
gradient through 100%. Values above the selected maximum are black. The three compact
handles set the minimum, middle, and maximum color anchors; moving them recolors cached
tiles immediately and does not rerun the sequence calculation.

In **Orientation** mode, forward and reverse matches have distinct colors. Direction
comes from the canonical orientations of verified matching k-mers. A weakly supported
color should not be treated as a confident strand call.

Hover over the plot to see the identity estimate and exact X/Y coordinate intervals.
Areas outside a shorter selected record are blank.

## Navigate

* Use the mouse wheel or trackpad to zoom around the pointer.
* Drag the plot to pan.
* Select **Reset view** to return to the complete comparison.
* Change either sequence selector at any time to start another comparison.

When entering a new level, the existing lower-resolution image is enlarged immediately.
Quick tiles then replace it, followed by detailed tiles if the viewport remains current.
Moving elsewhere cancels obsolete detailed work.

At maximum zoom, each plot position represents a k-mer start rather than an approximate
window sketch. Exact canonical k-mer matches are shown. In similarity mode their color
identifies the X-axis base using the usual genome-browser palette: A green, C blue,
G orange, and T red.

## Controls

| Control | Effect |
| --- | --- |
| X sequence / Y sequence | Select the two FASTA records to compare |
| Similarity / Orientation | Switch coloring without recomputing tiles |
| Identity range | Set the white threshold, gradient midpoint, and black threshold from 80% to 100% |
| Reset view | Return to the full comparison and redraw the overview |
| Clear | Remove loaded sequences, annotations, and cached results |

### Advanced controls

Advanced controls are collapsed by default.

| Control | Meaning |
| --- | --- |
| Plot detail | Full-view matrix dimension: 500, 1,000, 2,000, or 4,000 cells per axis |
| Quick accuracy | Registers used for the first visible estimate; default 256 |
| Detailed accuracy | Registers used for background refinement; default 2,048 |
| K-mer length | Canonical k-mer length used for sketching and terminal exact matching; default 21 |

Plot detail changes the number of independently calculated matrix cells, not the CSS
size of the plot. The plot expands with the browser window while retaining the selected
scientific resolution.

Register count controls sampling accuracy and cost. More registers generally reduce
variance but require more construction time, comparison work, and memory. It is not an
exact k-mer sampling percentage because register occupancy varies with sequence length,
complexity, and duplicate k-mers. The quick count cannot exceed the detailed count.

Changing a scientific control invalidates incompatible cached levels and starts a new
quick view. For routine navigation, the defaults are the recommended starting point.

## Add BED, GFF3, or GTF features

Drop a BED, GFF3, or GTF file directly on the X or Y axis. You may also double-click an
axis to open its feature-file chooser.

The application checks that the annotation contains the selected FASTA record name.
It accepts either the complete FASTA header or the first whitespace-delimited header
token. If no annotation record matches, the file is rejected rather than being drawn
against the wrong sequence. Coordinates are also checked against the sequence length.

BED coordinates must be zero-based and half-open. GFF3 and GTF coordinates must follow
their standard one-based inclusive convention. BED blocks and GFF/GTF exon or CDS
children are drawn as box-and-stick models. Dense views are capped at 500 visible
feature models per axis to keep navigation responsive.

If names do not match, inspect the first column of BED or the `seqid` column of GFF/GTF
and compare it with the selected FASTA header. Common mismatches include `chr1` versus
`1` and accession version suffixes.

## Progress and memory

The small donut beside the status text shows progress for the current foreground work.
The quick viewport is always completed and painted before detailed construction begins.

The compact memory value estimates packed sequence storage, Wasm structures, tile
arrays, and graphics textures. It does not include every byte owned by the browser or
graphics driver. Caches have bounded least-recently-used policies, but the current
overview and visible fallback tiles are protected and can temporarily exceed their
nominal budgets.

WebAssembly memory normally remains at its session high-water allocation even after
objects are discarded, although that space can be reused. Use **Clear** to remove live
application data. Reload the page to recreate the Wasm instance and fully reset the
browser session.

## Privacy and persistence

moddotplot-rs does not intentionally transmit loaded sequence or annotation bytes,
and it contains no analytics or application server API. The static hosting provider
can still observe ordinary page and asset requests, and browser extensions operate
outside the application's control. See [Privacy and local data handling](PRIVACY.md).

Sessions are not persisted. Reloading or closing the tab discards the application
state. Keep your source FASTA and annotation files available if you need to recreate a
view.

## Current limitations

* v0.1 is a preview and has not completed the full scientific release-validation plan.
* Very large records are limited by available browser memory; sharding and disk spill
  are planned before claiming robust 1 Gb operation.
* Identity estimates below roughly 80% are not a target operating regime and are shown
  as white by default.
* Data and high-resolution image export are not implemented yet.
* WebGL context recovery and automated cross-browser visual regression remain planned.

For implementation evidence and open validation work, see
[Implementation status](STATUS.md).

## Troubleshooting

### The application does not open from a downloaded folder

Serve the production directory through an HTTP server. Developers can run the Vite
development server as described in the [README](../README.md).

### A compressed FASTA is rejected

Confirm that the filename and bytes are gzip-compatible and that the browser is
current. As a fallback, decompress the file before loading it.

### An annotation file is rejected

Check the record-name convention and coordinate system. The application deliberately
refuses tracks that do not appear to belong to the selected sequence.

### Navigation becomes slow after extensive use

Wait for active work to finish, reduce Plot detail or register counts, or choose
**Clear** and reload the input. Reload the page if you also need to release the Wasm
linear-memory high-water allocation.

### The plot is empty

Confirm that both axis records are selected, then reset the view. An honestly blank
plot can also mean that the sequences have no detectable k-mer containment above the
current heatmap minimum.
