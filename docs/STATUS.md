UI smoke test is necessary, but not sufficient, evidence of scientific correctness.

## Working vertical slice

The current application provides:

* streaming multi-file, multi-record FASTA parsing in a dedicated worker;
* two-bit packed sequence plus a validity bitmap, without a chromosome-wide hash array;
* independent x/y sequence selection, including self comparisons through the same API;
* ntHash2 fixed-register b-bit similarity with HLL cardinality, containment scoring,
  and a word-parallel bit-sliced comparison kernel;
* separate similarity and canonical-strand direction coloring;
* plot-detail presets explicitly labeled with their 500, 1000, 2000, or 4000-cell
  initial matrices;
* 256 by 256 on-demand zoom tiles, byte-bounded LRU axis and graphics caches,
  coordinated worker/renderer eviction, cancellation by viewport generation, and a
  one-tile prefetch halo;
* a 256-register quick pass at every sketch level followed by configurable detailed
  refinement after a browser-paint acknowledgement, with stale refinement queues
  preempted by navigation;
* exact canonical k-mer tiles at maximum zoom, colored by the x-axis base with the
  standard A/C/G/T genome-browser palette in similarity mode;
* pointer-centered zoom, drag pan, reset, three-point identity recoloring, sparse
  coordinate axes, and compact identity/coordinate hover;
* real signature-construction progress, a compact status-line progress donut, and
  estimated application-memory reporting;
* BED3-12, GFF3, and GTF feature tracks with selected-record and coordinate validation;
* immutable active tile levels so a zoomed-out view cannot be contaminated by stale
  higher-resolution tiles;
* a render-independent numeric tile contract reserved for later export.

On the 4 Mb ModDotPlot Arabidopsis centromere fixture, the development build rendered
the default 1000 by 1000 overview in 1.1 seconds on the development Mac. An 8000-cell
zoom level and exact k-mer mode both completed without browser console errors.

The earlier progressive CHM13v2.0 chromosome 1 run (248,387,328 bp) took 2.162 seconds
to parse, completed overview signatures at 5.429 seconds, completed the 256-register
1,000 by 1,000 overview at 5.623 seconds, and completed 2,048-register refinement at
6.106 seconds. Estimated application memory was 195.1 MiB. A 4,096-register
cancellation check began a newly zoomed quick viewport 217 ms after navigation. See
the [progressive benchmark](benchmarks/2026-08-28-progressive-chm13-chr1.md). These
numbers predate the separated quick/detailed construction and byte-budgeted caches;
they are retained as historical observations, not current performance guarantees.

## Scientific evidence in the test suite

The Rust suite currently verifies:

* packed DNA, ambiguity breaks, reverse complements, and range coordinates;
* streaming FASTA behavior across arbitrary chunk boundaries;
* MashMap3-compatible MurmurHash vectors pinned to implementation commit `1a07d0e`;
* bounded-memory rolling `(w,s)` minmer intervals against independent bottom-s
  construction for every window, including ambiguous and low-complexity fixtures;
* the minmer interval-length window guarantee;
* coordinated bottom-s containment and direction semantics;
* optimized bit-sliced register comparisons against the scalar implementation;
* register-inverted all-pairs comparisons against the same scalar implementation;
* one-pass bounded exact sparse-core retention and exact directed containment;
* range-only zoom summaries against the same section of a whole-level summary;
* exact canonical k-mer forward, reverse-complement, mismatch, ambiguous, and padded
  cells;
* b-bit ANI error against exact k-mer sets and the MashMap bottom-s distribution.

The full Phase 0 harness now covers all required synthetic cases and a CHM13 chr1
higher-order alpha-satellite sample. The verification-gated b-bit candidate had mean
absolute error 0.000861 across synthetic fixtures and worst-fixture p95 0.014825; on
the CHM13 repeat sample those values were 0.000857 and 0.002077. See the
[Phase 0 report](benchmarks/2026-08-28-phase0.md).

The backend-v1 benchmark selected ntHash2 but rejected uncorrected direct OPH because
cardinality-imbalanced windows can have high containment and very low Jaccard. The
backend-v2 benchmark resolves that failure with an exact bounded sparse-core channel.
Its original zero-miss sweep selected 8,192 hashes and an eight-expected-match
threshold. The interactive requirement was subsequently relaxed from a guarantee to
a probability target. Production Wasm now uses ntHash2, a 2,048-hash cap, and exact
detailed correction only when the modeled probability of at least one true register
match at 80% ANI is below 99% (approximately 4.605 expected matches). Quick
256-register tiles intentionally remain approximate. See
[ADR 0003](adr/0003-progressive-estimation-policy.md) and the historical
[adaptive backend decision](benchmarks/2026-08-28-adaptive-backend-decision.md).

The current statistical fixture requires mean ANI error below 0.015 and 95th
percentile error below 0.035 against exact sets. Against the MashMap bottom-s
reference it requires mean error below 0.02 and 95th percentile error below 0.04.
The full Phase 0 matrix confirms these gates for the verification-gated b-bit
candidate; the final release epsilon and parameter tiers remain to be selected.

## Release blockers

The application must not yet be described as research-validated. The principal open
work is:

1. Add sequence and sketch sharding plus transient OPFS spill. The current contiguous
   in-memory representation is not approved for the stated 1 Gb limit.
2. Re-run and automate CHM13 pairwise benchmarks for the separated progressive
   pipeline, including peak browser and GPU memory.
3. Add robust WebGL context restoration, worker-failure tests,
   browser compatibility CI, and visual regression fixtures.
4. Quantify the revised probability-based sparse policy across broader simulated and
   biological contexts; it intentionally no longer promises zero window loss.
5. Complete a scientific validation report before a release version is tagged.

Persistence and data export intentionally remain later extension points. Numeric tile
generation is independent of WebGL so those features do not require changing the
scientific calculation.
