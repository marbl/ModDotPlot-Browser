# Privacy and local data handling

> **Note:** This project was generated by ChatGPT 5.6 Sol under the direction of Adam Phillippy and Alex Sweeten. For analyses intended for publication, please use the official [ModDotPlot CLI](https://github.com/marbl/ModDotPlot) and cite the [ModDotPlot paper](https://doi.org/10.1093/bioinformatics/btae493).

ModDotPlot Browser is designed to process genomic data locally in the user's browser.

## Application behavior

The current application:

* reads FASTA, FAI, GZI, BED, GFF3, and GTF files, including gzip- and BGZF-compressed
  sequence and annotation versions where supported, through browser file APIs;
* parses and sketches sequences in a dedicated Web Worker and WebAssembly instance;
* renders numeric results through WebGL2;
* makes no application API calls;
* includes no analytics, advertising, telemetry, CDN assets, or runtime package
  downloads; and
* does not intentionally upload sequence, annotation, sketch, or plot data.

The built application is a set of static files. It still requires HTTP or HTTPS
hosting because browsers restrict module workers and WebAssembly on `file://` pages.
The hosting provider can observe normal requests for the application files, including
IP address and browser metadata according to that provider's policy. Loaded genomic
files are not part of those requests.

## Memory and lifetime

Loaded data and calculated results are held in browser memory for the current tab.
ModDotPlot Browser does not persist sessions in IndexedDB, local storage, or OPFS.
Selecting **Clear** removes live application records and cache entries.
Reloading or closing the page destroys the worker and Wasm instance.

For indexed FASTA, the worker retains browser `File` references and validated index
metadata so it can read a selected record later. This is local random access to the
user-selected file, not an upload or a persistent copy. Records already requested by a
plot remain packed in the current Wasm session for reuse until Clear, replacement, or
page close.

WebAssembly linear memory can remain at a high-water allocation until the page is
reloaded, even after the application has released the objects that occupied it. The
memory is locally reusable and is not evidence of a network transfer.

## Boundaries of this statement

Browser extensions, modified browsers, operating-system services, developer tools,
and the policies of the static host are outside ModDotPlot Browser's control. Users
handling sensitive or controlled genomic data should use a trusted browser profile,
review the deployed build and hosting environment, and apply their institution's data
governance requirements.

Future persistence, remote collaboration, or telemetry features must be opt-in,
documented here, and reviewed as a change to the application's privacy model.
